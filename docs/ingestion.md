# HKMA Regulatory Document Ingestion

The pipeline discovers selected English documents from the verified HKMA stablecoin topic page, preserves originals, extracts and chunks text, validates results and writes them to SQLite. The fixed allowlist contains two PDFs and one HTML announcement; the guideline remains the default single-document target. Topic-page discovery and batch ingestion are documented in the [discovery guide](discovery.md). The local real-data sample contains 12 documents. PDFs use physical-page boundaries; HTML uses body selectors and character offsets. See the [source registry](source_registry.md) for scope and validation records. Existing Streamlit and demo data remain independent.

## Installation and Execution

Requires Python 3.10+ and SQLite 3.38+ with JSON functions. Run from the repository root in an activated Python virtual environment:

```powershell
python -m pip install -r requirements-ingestion.txt
$env:PYTHONPATH = Join-Path (Get-Location) 'src'

# Only when the database does not exist; never overwrites an existing database.
python -m virtual_asset_agent init-db

# Upgrade an existing v1 database once; no-op for v2, unnecessary for new databases.
python -m virtual_asset_agent migrate-db

# Ingest a real document, then rerun to verify reuse.
python -m virtual_asset_agent ingest --source hkma
python -m virtual_asset_agent ingest --source hkma

# Second target: 2024 consultation conclusions. URL must be on the verified allowlist.
$target = 'https://www.hkma.gov.hk/media/eng/doc/key-information/press-release/2024/20240717e3a1.pdf'
python -m virtual_asset_agent ingest --source hkma --url $target
python -m virtual_asset_agent ingest --source hkma --url $target

# Third target: HTML announcement; publication date comes from its article header.
$article = 'https://www.hkma.gov.hk/eng/news-and-media/press-releases/2024/07/20240717-3/'
python -m virtual_asset_agent ingest --source hkma --url $article
python -m virtual_asset_agent ingest --source hkma --url $article

# Offline tests: no official-site requests or changes to the real database.
python -m pytest tests -q -p no:cacheprovider
```

The original workspace database has already been backed up and migrated to v2, so ingestion can run directly there. init-db rejects existing databases. To reproduce from an empty database, choose an unused independent path:

```powershell
python -m virtual_asset_agent init-db --db data/ingestion/hkma-reproduction.sqlite
python -m virtual_asset_agent ingest --source hkma --db data/ingestion/hkma-reproduction.sqlite
python -m virtual_asset_agent ingest --source hkma --db data/ingestion/hkma-reproduction.sqlite
```

The CLI outputs JSON. A new result has status=created; identical original bytes and processing versions return reused without increasing document, evidence-version, extraction, chunk or label counts. Verified HTML csrf_token-only changes also reuse evidence and extraction, while every successful HTML run adds an html_observations row and preserves its full response bytes. Success returns 0; failure returns 1. MAS and non-allowlisted URLs are rejected before network access. A fixed target must still appear on the live topic page; missing links fail rather than selecting a different document. Single-document runs process one file; failure does not prevent a later run for another file.

Topic snapshots are stored in raw and referenced by logs, not counted as additional regulatory documents. Processing manifests use content hashes rather than execution times, allowing reuse. Changes to code, dependencies or chunking configuration create new extractions while preserving existing evidence.

Originals and manifests are fully written to temporary files in the destination directory, then atomically published by hard link. Existing files must match byte-for-byte. The filesystem must support local hard links; unsupported environments fail explicitly rather than overwriting files.

## Inspecting Records

Run these queries in a SQLite client to inspect documents, originals and processing versions:

```sql
SELECT d.source_url, v.content_sha256, v.raw_path,
       v.collected_at, v.last_collected_at,
       e.extraction_id, e.title, e.published_at,
       e.pipeline_version, e.metadata_evidence
FROM documents d
JOIN document_versions v USING (document_id)
JOIN extractions e USING (version_id)
ORDER BY e.processed_at;

SELECT extraction_id, COUNT(*) AS chunk_count,
       MIN(page_start) AS first_page, MAX(page_end) AS last_page
FROM chunks GROUP BY extraction_id;

PRAGMA foreign_key_check;
PRAGMA integrity_check;
```

Full responses are saved first. PDFs register versions before parsing. HTML registers or reuses a version after layout validation and change comparison; layout failures retain only originals and logs. Extractions, chunks, asset classifications and successful HTML observations commit together; any failure rolls back the result. Download success does not establish parsing success.

## Failures and Limitations

- Download failures: inspect download/discovery logs and network/proxy settings. trust_env=false uses direct connections with TLS verification enabled.
- Source-page or cover-layout changes: fail explicitly; inspect the live source, update fixtures/rules and rerun tests.
- Blank or image-only PDFs: report unsupported OCR, preserve originals and create no successful extraction.
- Unextracted dates or stages: retain NULL/unknown with a specific reason; do not invent dates or claim that unextracted information is absent from the original.
- Tables: preserve text and physical pages, without reliable table structure; is_table remains NULL.
- HTML changes: only the verified csrf_token-only difference reuses evidence. Other unknown page changes produce page_changed and a new version; article, date, language or attachment-link changes produce content_changed. Fingerprints never replace byte hashes.

Compatibility: migrate v1 to v2 additively with migrate-db; do not reinitialize existing databases. HTML locators use metadata_evidence with NULL page fields. Code changes may create processing versions without overwriting history. See [HTML change detection](html_incremental.md) for fields, migration and state semantics. Existing dependencies and teammate files remain unchanged. Link discovery and bounded batch ingestion are implemented as described in the discovery guide.

Teammate files, original dependencies and demo data were preserved. The schema was extended and migrated to v2. New code, configuration, tests and documentation can be reviewed independently. Real databases, originals and logs are local artifacts. This delivery does not commit or push changes automatically, and .gitignore is unchanged.

For HTML, status describes processing (created/reused), while change_type describes content comparison. Changed code with unchanged source content can yield created and unchanged together. raw_path/content_sha256 describe the current response; evidence_raw_path/evidence_content_sha256 identify the extraction's original. response_differs_from_evidence states whether their bytes differ. The evidence version's collection time is not necessarily the current fetch time; use html_observations.collected_at.

Use `python -m virtual_asset_agent discover --source hkma` to inspect candidates and `python -m virtual_asset_agent ingest-discovered --source hkma --limit 10` to ingest a batch. `--new-only` skips successful known documents, including possible updates to them; omit it when checking for updates.

Read real data with `python -m virtual_asset_agent.reader documents` or `python -m virtual_asset_agent.reader search --query "reserve assets"`; see [read-only queries](query.md). These commands do not ingest, read demo data or modify the database.
